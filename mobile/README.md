# HitchPoint phone apps (iPhone and Android)

The HitchPoint app is a native shell, built with [Capacitor 8](https://capacitorjs.com), that opens the live dashboard at `https://gethitchpoint.com/admin/`. Anything shipped to the dashboard shows up in the app right away; a store update is needed only when the native part changes (icons, permissions, plugins).

| | |
| --- | --- |
| App name | HitchPoint |
| Bundle / application ID | `com.gethitchpoint.app` (permanent once the first build is uploaded to either store) |
| iPhone | iOS 15 and later |
| Android | Android 7 (API 24) and later; targets API 36, which Google Play requires for new apps from August 31, 2026 |

## What's here

- `ios/` and `android/`: the native projects, generated by Capacitor and committed.
- `capacitor.config.json`: app ID, name, the dashboard address, the splash screen.
- `www/offline.html`: shown when the phone has no connection (it ships inside the app).
- `assets/`: icon and splash sources made from `design/brand/`. After changing them, run `npm run icons`.
- `.github/workflows/mobile.yml` (repo root): on every change here, checks that both apps build, and saves an Android test app (`app-debug.apk`) on the run's page.

### How the dashboard behaves inside the app

The dashboard (`admin/public/admin.js`) notices it's running in the app and:

- opens other websites (Stripe, maps, Google) and public pages meant for a new tab (legal pages, the business's website, proposals) in the in-app browser, so the dashboard stays underneath;
- opens pages that need the login (job photos, W-9s) in place: swipe from the left edge to go back on iPhone, or use the back button on Android;
- sends Stripe setup to `/admin/app-done.html` ("tap Done") instead of the dashboard, then refreshes the owner's Stripe status when they close it;
- hides the "Add to home screen" tip.

The app adds `HitchPointApp/1.0` to its browser identity, which is how the server tells the app apart.

## Google Play builds and the upload key

GitHub builds the Google Play app bundle (`app-release.aab`) on main and whenever someone clicks **Run workflow** on the Phone apps workflow. It's saved under **Artifacts** on the run's page for 90 days. Each build's version code is the run number, so every upload is higher than the last.

The bundle is signed with HitchPoint's **upload key**, `android/upload-keystore.p12`. The key file is locked with the `ANDROID_UPLOAD_PASSWORD` repository secret, and that password lives only in that secret and Aaron's password manager. The first run on main after the secret is added creates the key and commits it with `[skip render]`. Google Play App Signing holds the real app signing key; if the upload key or its password is ever lost, the account owner can ask Google for an upload key reset in Play Console → Test and release → App integrity.

On pull requests, the workflow checks that a release build signs using a throwaway key that it deletes afterwards.

## Build it yourself

```bash
cd mobile
npm ci
npx cap sync          # after changing capacitor.config.json or plugins
npx cap open ios      # Xcode, on a Mac
npx cap open android  # Android Studio
```

## Before the stores will accept it

Both stores reject apps that are only a website in a frame, and both require a way to delete an account from inside the app. Still to build, in order:

1. **Delete my account** (Apple guideline 5.1.1(v), Google Play's account deletion policy). Needs a decision on what HitchPoint must keep after deletion (payment records, signed proposals, W-9s) and for how long; the app must say so.
2. **Push notifications** for new requests and payments: the main thing the app does that a website can't, and the strongest answer to Apple's "minimum functionality" rule (4.2). Needs a Firebase project (Android) and an Apple push key.
3. **Links that open the app**: password reset, invitations and Stripe returns open in the app instead of the browser (Apple universal links and Android App Links). Needs the Apple Team ID and the Android signing certificate fingerprint.
4. **A reviewer login** with example requests, quotes and a schedule, plus review notes.
5. **Store listings**: screenshots, descriptions, privacy answers (Apple's App Privacy labels, Google's Data safety form) and the privacy policy link (https://gethitchpoint.com/legal/privacy).
6. **Signing and upload**: Android signing is set up (above); the first bundle is uploaded by hand in Play Console. Still to do: an App Store Connect API key for TestFlight, and a Google Play service account so later Android builds upload from GitHub.

## Accounts Agilities needs first

- **D-U-N-S number** for Agilities Tech, LLC (free from Dun & Bradstreet). Both stores need it for a company account.
- **Apple Developer Program**, enrolled as the organization Agilities Tech, LLC: $99 a year. Apple doesn't accept DBAs, so the App Store lists the seller as Agilities Tech, LLC; the app itself is still called HitchPoint.
- **Google Play Console**, as an organization account for Agilities Tech, LLC. Personal accounts made after November 13, 2023 must run a 14-day closed test with at least 12 testers before release.
